# Relay

A message in Telegram becomes a GitHub Issue, a plan, code and a release — on
your own Mac, with your Claude subscription. You make three decisions: design,
plan, deploy. Everything else runs as GitHub Actions jobs on a self-hosted
runner, driven by a Claude Code plugin.

**Status: v0 (walking skeleton).** The chain *message → Issue → discussion →
`/ticket` → triage → plan → approval* works end to end. Implement, test,
review and release arrive in v1.

## How it works

| Part | What it is | Where it runs |
|---|---|---|
| **Plugin** | Claude Code skills for each stage (`discuss`, `ticket`, `triage`, `plan`, `init`) and the `planner → architect → critic` agents | installed into Claude Code (`relay@relay`) |
| **Workflow** | `.github/workflows/relay.yml`, generated by `/relay:init`; one job per stage, each `relay stage <name>` | GitHub Actions, self-hosted runner on your Mac |
| **Bot** | `relay bot`: Telegram in, GitHub out; polling only, no inbound port, no database | LaunchAgent on the same Mac |

The three parts talk only through the GitHub Issue: labels are the state,
comments are the results, slash commands are the controls. Everything the bot
does you can also do by hand in the GitHub UI. The contract is
[docs/protocol.md](docs/protocol.md).

Relay uses the official Claude Code login of a subscription on the runner.
There is no API key anywhere, and a job refuses to run if it finds one.

## Setup (≤ 10 minutes, one secret)

Prerequisites: a Mac with Claude Code logged in (`claude auth login`), `gh`
logged in with `repo` and `workflow` scopes, a **private** repository on
GitHub for each project (see [Security](#security)), a bot token from
[@BotFather](https://t.me/BotFather).

Install the binary (pick one):

```sh
# a) a release binary
gh release download --repo masteine/relay --pattern "relay_*_darwin_$(uname -m | sed 's/x86_64/amd64/').tar.gz" --dir /tmp/relay --clobber
tar -xzf /tmp/relay/relay_*.tar.gz -C /tmp/relay && mkdir -p ~/.local/bin && mv /tmp/relay/relay ~/.local/bin/relay

# b) go install
GOBIN=~/.local/bin go install github.com/masteine/relay/cmd/relay@latest

# c) from source
git clone https://github.com/masteine/relay && cd relay && go build -o ~/.local/bin/relay ./cmd/relay
```

`~/.local/bin` must be on your PATH (and it is on the runner's: `relay add`
puts it there). Then:

```sh
relay setup                          # once per Mac: checks, plugin, token, bot service
```

In each project, inside Claude Code:

```
/relay:init                          # three questions → relay.yml, the workflow, labels; commits and pushes
```

then

```sh
relay add todo owner/repo            # bot alias + self-hosted runner for this repository
relay doctor                         # anything wrong, if anything
```

Now send the bot `todo: <what you want>` and follow the buttons.

## Commands in an Issue

`/ticket` closes the discussion and writes the task into the Issue body;
`/approve` lets the pipeline continue past a gate; `/retry` repeats a failed
stage. The bot's buttons post exactly these comments.

## Costs

Every stage comment ends with turns, tokens, time and an API-price estimate,
plus a machine-readable marker for `/stats` (v1). Thinking stages (triage,
plan, review) run on `opus` by default; `fable` is an explicit opt-in in
`relay.yml`, because in headless runs it can bill usage credits beyond the
subscription.

## Development

```sh
go test ./...                                              # 120+ tests, all offline
RELAY_IT_REPO=owner/repo go test -tags integration ./internal/bot/core/   # the bot against a real repository
```

## Security

Relay runs Claude Code with tool access on your own Mac, driven by text from
GitHub Issues. Keep that text trusted:

- **Use private repositories only.** A self-hosted runner on a public
  repository lets anyone who can open an Issue or a pull request run jobs on
  your machine; GitHub [advises against it](https://docs.github.com/en/actions/hosting-your-own-runners/managing-self-hosted-runners/about-self-hosted-runners#self-hosted-runner-security).
- **Be the only writer.** The runner works as your macOS user, with your
  Keychain (gh, Claude and Telegram credentials). Anyone with write access
  can push a workflow that runs on it, so connect only repositories where you
  are the sole collaborator, or run the runner under a dedicated macOS user.
- `relay stage route` does nothing in a public repository and acts only on
  the configured owner's labels and commands; comments from others are passed
  to the model marked as data, not instructions.
- The bot answers only the chat and user captured during `relay setup`.

To report a vulnerability, see [SECURITY.md](SECURITY.md).

## A note on terms of use

Relay works through the official ways Claude Code authenticates (`claude auth
login` on the runner, or `claude setup-token` for CI). Whether a subscription
may be used this way is Anthropic's call; if that changes, the runner is the
only part that has to change.
